# Архітектура (`/architecture`)

## `architecture-hero`

- Заголовок: `Architecture` → **Архітектура**.
- Підпис: **Дослідіть високошвидкісні та стійкі внутрішні механізми координаційної тканини MCP Agent Mail.**

## `overview` — топологія системи

- Брова: `Agent Mail Topology` → **Топологія Agent Mail**.
- Заголовок: `CLI to Archive Dataflow` → **Потік даних від CLI до архіву**.
- Kicker: **Практична карта шляху запитів MCP через обробники сервера до SQLite і перевірного зберігання на Git.**
- Пояснення:
  - Команди CLI і режиму робота запускають інструменти MCP.
  - Обробники записують/читають SQLite.
  - Фонові працівники сховища об'єднують файлові записи в історію Git.

## `mcp-layer` — інтеграційний шар MCP

- Брова: `Integration Layer` → **Інтеграційний шар**.
- Заголовок: `MCP Architecture` → **Архітектура MCP**.
- Kicker: **Model Context Protocol стандартизує обмін між середовищем агента і координаційним шаром SQLite.**
- Пояснення:
  - Система відкриває рівно 34 інструменти і понад 20 ресурсів лише для читання.
  - Інтерфейс — чистий JSON-RPC через `stdio`, сумісний із сучасними агентами кодування.

## `dual-write` — двоконтурний запис

- Брова: `Storage Guarantees` → **Гарантії зберігання**.
- Заголовок: `Dual-Write Pipeline` → **Двоконтурний конвеєр запису**.
- Kicker: **Надшвидкі запити і незмінний перевірний слід у Git одночасно.**
- Пояснення:
  - Кожна подія йде двома паралельними шляхами.
  - Перший шлях: SQLite у режимі `WAL` для миттєвої видимості і швидкого FTS5-пошуку.
  - Другий шлях: `Write-Behind Queue` до файлового архіву.

## `coalescer` — об'єднувач комітів

- Брова: `Write Amplification` → **Підсилення запису**.
- Заголовок: `Commit Coalescer` → **Об'єднувач комітів**.
- Kicker: **Усуває суперництво за блокування Git через пакетування конкурентних записів агентів.**
- Пояснення:
  - При масових одночасних записах прямий шлях до Git призводить до конфліктів блокувань.
  - Об'єднувач перехоплює високочастотні записи і пакетує їх.
  - Під піком навантаження можливо близько 9.1x зменшення кількості комітів.

## `product-bus` — федерація проєктів

- Брова: `Cross-Project Federation` → **Міжпроєктна федерація**.
- Заголовок: `The Product Bus` → **Шина продукту**.
- Kicker: **Федерація кількох репозиторіїв у єдиний координаційний шар без спільної історії Git.**
- Пояснення:
  - `project_keys` відображаються у спільний простір продукту.
  - Агенти можуть шукати, перевіряти резервування і надсилати повідомлення між різними кодовими базами.

## `search` — гібридний пошук V3

- Брова: `Context Retrieval` → **Добування контексту**.
- Заголовок: `Hybrid Search V3` → **Гібридний пошук V3**.
- Kicker: **Двошарове добування: лексика SQLite FTS5 + семантичні вектори, злиті через RRF.**
- Пояснення:
  - Лексичний (`BM25`) і семантичний шари працюють паралельно.
  - За відмови семантики система переходить у лексичний режим.
  - За проблеми в SQLite — резервний хронологічний перегляд, щоб агент не лишався "сліпим".

## `reliability` — стійкість системи

- Брова: `System Resilience` → **Стійкість системи**.
- Заголовок: `Reliability Internals` → **Внутрішні механізми надійності**.
- Kicker: **Незалежні фонові цикли, тригери протитиску, відновлення після виснаження пулу.**
- Пояснення:
  - За переповнення WBQ (поріг 128) сервер вводить протитиск.
  - Це дає фоновим циклам (метрики, цілісність, збереження) час безпечно розвантажити буфери.
