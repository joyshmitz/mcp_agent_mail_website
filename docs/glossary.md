## Терміни (переклад коротких і розгорнутих визначень)

### Acknowledgment — Підтвердження отримання

- Коротко: **Підтвердження, що повідомлення отримано.**
- Докладно: якщо повідомлення надсилається з `ack_required=true`, агент-одержувач має явно підтвердити отримання. Система відстежує стан підтвердження і може показувати прострочені підтвердження оператору.

### Advisory Lock — Дорадче блокування

- Коротко: **Неблокувальний сигнал координації.**
- Докладно: резервування файлів в Agent Mail дорадчі: вони показують конфлікти та взаємодіють із `pre-commit guard`, але можуть бути обійдені. Це прибирає глухі блокування і зберігає видимість власності.

### Agent Identity — Ідентичність агента

- Коротко: **Запам'ятовуване стале ім'я агента.**
- Докладно: кожен агент отримує ім'я формату прикметник+іменник (`GreenCastle`, `BlueLake`, `RedHarbor`), що може зберігатися між сеансами. Ідентичність прив'язана до проєкту і містить метадані програми/моделі. Важливо: ідентичність — це не процес і не конкретний запуск CLI; процес може зникнути, а ідентичність і пов'язаний координаційний стан лишаються зрозумілими системі.

### Agent Process — Процес агента

- Коротко: **Конкретний живий запуск CLI або runtime агента.**
- Докладно: процес агента — це тимчасове виконання (`codex`, `claude-code`, `gemini` тощо), яке може завершитися аварійно, втратити контекст або бути вбите оператором. Процес ефемерний; Agent Mail не покладається на його безперервне існування для збереження координаційного стану.

### Agent Session — Сесія агента

- Коротко: **Період роботи агента в межах певного контексту.**
- Докладно: сесія охоплює конкретний захід агента в проєкт, отриману вхідну, активні гілки й поточну задачу. Нова сесія може відновити попередню ідентичність, але не є тією самою подією виконання; саме тому resume у Agent Mail робиться через читання стану системи, а не через "пам'ять процесу".

### Agent Ephemerality — Ефемерність агента

- Коротко: **Допущення, що агент може безслідно зникнути як процес.**
- Докладно: Agent Mail проектується під реальність, де агентний процес часто переривається, очищається або втрачає контекст. Через це резервування мають `TTL`, історія листування зберігається окремо, а resume робиться через вхідну, гілки і пошук, а не через надію на безперервне життя одного runtime.

### Agent Mail — Agent Mail

- Коротко: **Координаційна інфраструктура для агентів кодування ШІ.**
- Докладно: MCP Agent Mail дає повний робочий контур багатoагентної розробки: ідентичності, гілкові повідомлення, резервування файлів, пошук, перевірні журнали й операторські інструменти на SQLite + Git.

### Backpressure — Протитиск

- Коротко: **Керування потоком у перевантаженні.**
- Докладно: коли вхідна швидкість перевищує можливості обробки, система відсікає низькопріоритетні роботи (наприклад, `archive_repair`) і завжди приймає високопріоритетні операції (`send_message`, `fetch_inbox`). Це запобігає каскадним відмовам.

### Build Slot — Слот збірки

- Коротко: **Керування паралельністю компіляції.**
- Докладно: оренда, що обмежує кількість агентів, які одночасно виконують ресурсоємні дії (`cargo build`). Агенти беруть, подовжують і звільняють слоти.

### Commit Coalescer — Об'єднувач комітів

- Коротко: **Пакетує коміти Git для ефективності.**
- Докладно: замість коміту на кожну операцію запису система об'єднує багато записів у меншу кількість комітів. У стрес-тестах: `100` записів → `11` комітів.

### Contact Handshake — Контактне рукостискання

- Коротко: **Протокол встановлення зв'язку між агентами.**
- Докладно: до обміну повідомленнями між агентами різних проєктів виконується рукостискання: `request_contact` надсилає запит, `respond_contact` приймає або відхиляє. Політики можуть дозволяти автовідповідь або блокування.

### Context Window — Контекстне вікно

- Коротко: **Бюджет токенів, доступний LLM.**
- Докладно: обмежений буфер токенів, який LLM може обробити за сеанс. Координаційний шум у чаті витрачає цей бюджет, що інакше пішов би на міркування і генерацію коду.

### Context Recovery — Відновлення контексту

- Коротко: **Повернення агента до робочого стану через дані системи.**
- Докладно: коли агент повертається після обриву, він відновлює контекст не з власної оперативної пам'яті, а з повідомлень, гілок, пошуку, резервувань і макросів на кшталт `macro_start_session` та `macro_prepare_thread`. Це ключова відмінність між "відновленням процесу" і "відновленням координаційного стану".

### Exclusive Reservation — Виключне резервування

- Коротко: **Одноосібна власність на файли під час редагування.**
- Докладно: якщо агент резервує файли з `exclusive=true`, інші агенти не можуть резервувати перетинні шляхи, доки строк не спливе або резервування не буде звільнено.

### File Reservation — Резервування файлів

- Коротко: **Дорадча оренда на шляхи файлів.**
- Докладно: агент заявляє намір редагування для шаблонів шляхів (`glob`, наприклад `src/auth/**/*.ts`) на певний `TTL`. Інші агенти бачать це і координуються; конфлікти стають видимими.

### FTS5 — FTS5

- Коротко: **Повнотекстовий рушій пошуку SQLite.**
- Докладно: вбудоване розширення SQLite для повнотекстового пошуку. Agent Mail індексує теми, тіла й метадані повідомлень, забезпечуючи дуже швидкий пошук без зовнішньої пошукової інфраструктури.

### Glob Pattern — Шаблон шляху `glob`

- Коротко: **Пошук шляхів із підстановками.**
- Докладно: шаблон типу `src/auth/**/*.ts` зі знаками підстановки. Резервуються не окремі файли, а шаблони, які покривають дерево каталогів.

### Human Overseer — Людина-наглядач

- Коротко: **Веб-інтерфейс для операторського втручання.**
- Докладно: інтерфейс на `localhost:8765/mail` дозволяє надсилати пріоритетні повідомлення агентам, переглядати вхідні, шукати повідомлення й контролювати резервування у всіх проєктах.

### Inbox — Вхідна скринька

- Коротко: **Черга повідомлень окремого агента.**
- Докладно: кожен зареєстрований агент має вхідну в межах проєкту. Отримання — через `fetch_inbox` або ресурс `resource://inbox/{agent}`.

### Macro — Макрос

- Коротко: **Багатокрокова операція MCP одним викликом.**
- Докладно: чотири макроси (`macro_start_session`, `macro_prepare_thread`, `macro_file_reservation_cycle`, `macro_contact_handshake`) стискають типові ланцюжки дій у передбачуваний виклик.

### MCP — Model Context Protocol

- Коротко: **Стандарт підключення моделей до зовнішніх інструментів і даних.**
- Докладно: Agent Mail відкриває 34 інструменти і 20+ ресурсів через MCP, тому сумісний з будь-яким агентом кодування, який підтримує MCP.

### MCP Resource — Ресурс MCP

- Коротко: **Поверхня даних лише для читання, що виявляється агентами.**
- Докладно: на відміну від інструментів (що виконують дії), ресурси дають швидке читання (`resource://inbox/{agent}`, `resource://thread/{id}`, `resource://agents` тощо) без накладних витрат інструментального виклику.

### Pre-Commit Guard — Запобіжник перед комітом

- Коротко: **Git-гачок для примусу правил резервування.**
- Докладно: `mcp-agent-mail-guard` встановлюється як `pre-commit`-гачок, перевіряє перетин закомічених файлів із чужими активними резервуваннями і блокує коміт. Обхід: `AGENT_MAIL_BYPASS=1`.

### Product Bus — Шина продукту

- Коротко: **Шар координації між репозиторіями.**
- Докладно: об'єднує кілька Git-репозиторіїв під одним продуктом; надає міжпроєктний пошук, агреговані вхідні і керування контактами.

### Project Key — Ключ проєкту

- Коротко: **Абсолютний шлях, що ідентифікує репозиторій.**
- Докладно: канонічний ідентифікатор проєкту в Agent Mail — абсолютний шлях до кореня репозиторію; використовується в інструментах і URI ресурсів.

### Robot Mode — Режим робота

- Коротко: **Неінтерактивний CLI для агентів.**
- Докладно: підкоманда `am robot` має 16 команд (`status`, `inbox`, `timeline`, `thread`, `search` тощо) з виводом `toon`, `JSON` або `Markdown` для машинного споживання.

### Shared Reservation — Спільне резервування

- Коротко: **Невиключне декларування доступу до файлів.**
- Докладно: за `exclusive=false` інші агенти теж можуть створювати перетинні резервування. Це корисно для сценаріїв читання, де важлива видимість, але не виключність.

### Stress Gauntlet — Стресовий випробувальний набір

- Коротко: **Набір з 10 сценаріїв перевірки виробничої готовності.**
- Докладно: охоплює конвеєри повідомлень на 30 агентів, 10 проєктів, пакетування комітів, відновлення застарілих блокувань, змішані навантаження, виснаження пулу, сталу пропускну здатність, "гуртові удари" і читання вхідних під бурею повідомлень.

### Thread — Гілка листування

- Коротко: **Групування повідомлень за `thread_id`.**
- Докладно: повідомлення з однаковим `thread_id` утворюють гілку; це зберігає контекст обговорення. Ідентифікатор гілки часто відповідає ідентифікатору задачі, наприклад `br-123` у канонічних прикладах проєкту.

### Tool Cluster — Кластер інструментів

- Коротко: **Логічне групування інструментів MCP.**
- Докладно: 34 інструменти поділено на 9 кластерів: інфраструктура, ідентичність, повідомлення, контакти, резервування, пошук, макроси, шина продукту, слоти збірки.

### Toon Format — Формат `toon`

- Коротко: **Токеноощадний формат виводу режиму робота.**
- Докладно: компактний формат за замовчуванням у TTY, придатний для швидкого сканування й мінімізації токенів. Альтернативи: `json`, `md`.

### TTL — Час життя

- Коротко: **Строк дії резервувань.**
- Докладно: резервування файлів і слоти збірки мають `TTL` (типово 3600 секунд). Перед спливом строк можна подовжити; прострочені записи прибираються автоматично.

### TUI — Термінальний інтерфейс користувача

- Коротко: **Операторська консоль у терміналі.**
- Докладно: інтерактивний інтерфейс на 15 екранів для панелей стану, перегляду повідомлень, гілок, агентів, пошуку, резервувань і здоров'я системи.

### WAL — Журнал попереднього запису

- Коротко: **Режим SQLite для безпечного відновлення після збоїв.**
- Докладно: `WAL` дозволяє паралельних читачів і одного записувача без блокувань читання. Agent Mail використовує `WAL`, щоб обслуговувати запити агентів паралельно з пакетним записом у фоні.

### Web UI — Веб-інтерфейс

- Коротко: **Операторський інтерфейс у браузері.**
- Докладно: `http://127.0.0.1:8765/mail` надає єдину вхідну, огляд проєктів, деталізацію повідомлень, пошук, резервування і форму Human Overseer.

### Write-Behind Queue — Черга відкладеного запису

- Коротко: **Буферизований асинхронний конвеєр запису.**
- Докладно: черга накопичує часті операції запису і зливає їх пакетними комітами з налаштованим інтервалом. Це відділяє затримку підтвердження від довговічного зберігання архіву.

## Поширені запитання (загальний FAQ)

### 1) Чим Agent Mail відрізняється від використання лише гілок Git?

Гілки ізолюють зміни коду, але не дають комунікації, ідентичності й координації між агентами. Agent Mail додає гілкові повідомлення, резервування файлів, пошук і операторську видимість поверх звичного Git-потоку.

### 2) Чи працює Agent Mail з будь-яким агентом кодування ШІ?

Так. Через MCP надаються 34 інструменти і 20+ ресурсів, тому підключається будь-який MCP-сумісний агент.

### 3) Що буде, якщо агент аварійно завершується під час резервування?

Резервування мають `TTL` (типово 3600 секунд) і спливають автоматично. Сценарії відновлення застарілих блокувань перевірені стрес-набором.

### 4) Запобіжник перед комітом обов'язковий?

Ні. Він добровільний і має обхід (`AGENT_MAIL_BYPASS=1`). Дорадчі резервування лишаються основним механізмом видимості конфліктів без жорстких блокувань.

### 5) Як працює міжпроєктна координація?

Шина продукту об'єднує репозиторії під спільною парасолькою. Після контактного рукостискання агенти можуть надсилати повідомлення і шукати через межі проєктів.

### 6) Яка вартість за продуктивністю?

Невелика. Стрес-набір утримує близько `~49 RPS` на 30 паралельних агентах. `WAL` + пул з'єднань тримають затримку низькою, об'єднувач комітів зменшує накладні витрати Git приблизно у `9.1x`.

### 7) Чи є сенс використовувати Agent Mail для сольного проєкту?

Так. Навіть один розробник виграє від перевірного сліду, структурованого пошуку і безконфліктного запуску кількох агентів у межах одного проєкту.

### 8) Як зберігається історія повідомлень?

Подвійно: SQLite для швидкого пошуку та Git-архів для довговічної, порівнюваної історії.

### 9) Які 9 кластерів інструментів?

Інфраструктура, ідентичність, повідомлення, контакти, резервування файлів, пошук, макроси, шина продукту, слоти збірки.

### 10) Чи потрібен окремий сервер?

Ні. Agent Mail — один двійковий файл (`am`), що обслуговує MCP і HTTP/Web UI без зовнішніх баз, брокерів чи хмарних служб.
