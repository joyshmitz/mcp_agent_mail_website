# Навігатор вивчення MCP Agent Mail українською

Цей набір файлів не просто перекладає інтерфейс сайту, а допомагає швидко побудувати правильну ментальну модель MCP Agent Mail: що саме координується, де лежить стан, як відновлювати роботу після збоїв і які поверхні системи призначені для людини, а які для агента.

## З чого починати

| Маршрут | Для кого | Що читати | Що стане зрозуміло | Орієнтовний час |
|---|---|---|---|---|
| **Швидкий старт** | Для першого знайомства з системою | `docs/getting-started.md` → `docs/glossary.md` → `docs/home.md` | Як запустити Agent Mail, які примітиви є базовими і чому система взагалі потрібна | 25-35 хв |
| **Оператор** | Для того, хто наглядає за кількома агентами | `docs/getting-started.md` → `docs/showcase.md` → `docs/architecture.md` → `docs/glossary.md` | Як спостерігати за роботою агентів, бачити конфлікти, читати сигнали стану і втручатися | 45-60 хв |
| **Архітектор** | Для того, хто хоче зрозуміти модель системи | `docs/spec-explorer.md` → `docs/architecture.md` → `docs/showcase.md` → `docs/glossary.md` | Як влаштовані шари MCP, зберігання, пошук, гілки повідомлень, резервування і операторські поверхні | 60-90 хв |

## Рекомендований перший прохід

1. Прочитайте `docs/getting-started.md`, щоб побачити базовий happy-path і набір основних макросів.
2. Перейдіть до `docs/glossary.md`, щоб відразу зафіксувати значення ключових термінів.
3. Прочитайте `docs/home.md`, щоб зрозуміти, які проблеми Agent Mail вирішує на практиці.
4. Відкрийте `docs/spec-explorer.md`, щоб побачити повну карту технічного корпусу.
5. Поглиблюйтеся через `docs/architecture.md` і `docs/showcase.md`, якщо вже потрібно розуміти внутрішню модель або операторські сценарії.

## Карта документів

- `docs/getting-started.md` — стартовий шлях: встановлення, перший цикл координації, макроси, типові сценарії запуску.
- `docs/glossary.md` — канонічні визначення термінів: ідентичність, гілка, резервування, підтвердження, шина продукту, TUI, MCP.
- `docs/home.md` — швидкий огляд цінності системи: які проблеми координації вона прибирає і чому це краще за наївні підходи.
- `docs/spec-explorer.md` — карта технічного корпусу: категорії, документи, інтерфейс читача, технічні поверхні.
- `docs/architecture.md` — системне пояснення: потік від інструментів MCP до SQLite та Git-архіву, пошук, надійність, федерація проєктів.
- `docs/showcase.md` — операторське читання через демонстрації: резервування, життєвий цикл повідомлення, контактне рукостискання, протитиск, TUI.
- `docs/flywheel.md` — ширший контекст екосистеми Agent Flywheel і взаємодія Agent Mail з іншими інструментами.
- `docs/hero-media.md` — переклад симулятора на головній сторінці: стрічка подій, глави ролика, субтитри, короткий технічний сценарій.
- `docs/system-pages.md` — службові стани й помилки маршрутизації сайту.

## Примітка щодо актуальності

Специфікації в `public/spec-docs/*.md` уже мають новішу таксономію, ніж у попередній версії цього перекладу. Канонічною картою технічного корпусу в українському наборі слід вважати `docs/spec-explorer.md`; саме її потрібно оновлювати першою при зміні структури Spec Explorer на сайті.
