# Оглядач специфікацій (`/spec-explorer`)

`/spec-explorer` — це не просто читач Markdown, а головна карта технічного корпусу MCP Agent Mail. Якщо `docs/getting-started.md` пояснює, як почати роботу, то цей документ показує, де шукати точне технічне пояснення для кожного шару системи.

## Як читати корпус специфікацій

1. Якщо ви знайомитеся з системою вперше, почніть з категорій **Базові поняття** і **Потоки координації**.
2. Якщо вас цікавить поведінка системи під навантаженням і під час збоїв, переходьте до **Надійності і безпечності** та **Зберігання і пошуку**.
3. Якщо ви впроваджуєте Agent Mail у наявний стек інструментів, прочитайте **Поверхні взаємодії** і **Міграцію та паритет**.
4. Якщо ви працюєте як оператор, спочатку дивіться блок `technical-surface`: він швидко показує, які інструменти, ресурси, екрани TUI і команди режиму робота взагалі існують.

## `spec-explorer-hero`

- Назва сторінки: `Spec Explorer` → **Оглядач специфікацій**.
- Опис сторінки: **Читайте технічний корпус MCP Agent Mail з миттєвим пошуком, фільтрами категорій і двопанельним режимом читання для реальної інженерної роботи.**
- Метрики:
  - `Documents` → **Документи**.
  - `Categories` → **Категорії**.
  - `Hotkeys` → **Гарячі клавіші** (`/ + Esc`).

## `spec-explorer-shell` — оболонка читача

### Верхня панель

- `Interactive Reader` → **Інтерактивний читач**.
- Пояснення: **Фільтруйте документи за категорією, миттєво шукайте і відкривайте окремий документ у виділеній панелі читання.**

### Плашки стану

- `Visible` → **Видимі**.
- `Categories` → **Категорії**.
- `Selection` → **Вибір**.
- Значення без активного документа: `None` → **Немає**.
- Якщо відкритий документ не входить у поточну вибірку, інтерфейс показує стан `Pinned` → **Закріплено**.

### Мобільний режим

- Кнопка `Back to Documents` → **Повернутися до документів**.

### Порожній стан настільного режиму

- `Select a Document` → **Оберіть документ**.
- Пояснення: **Оберіть специфікацію з лівої панелі, щоб завантажити структурований режим читання. Натисніть `/`, щоб перейти в пошук.**

### Пошук і фільтри

- Підказка поля: `Search docs by title, category, or description` → **Шукати документи за назвою, категорією або описом**.
- `Search spec documents` → **Пошук документів специфікацій**.
- `Clear search` → **Очистити пошук**.
- Пояснення під полем: `Showing X of Y documents` → **Показано X із Y документів**.
- Вкладка `All` → **Усі**.

### Порожній результат фільтра

- `No documents match this filter.` → **Немає документів, що відповідають цьому фільтру.**
- `Try another category or search term.` → **Спробуйте іншу категорію або інший пошуковий запит.**

## `technical-surface` — карта технічної поверхні

### Заголовок секції

- `Technical Surface Map` → **Карта технічної поверхні**.
- Пояснення: **Швидкий огляд усіх кластерів інструментів, ресурсів, екранів TUI і напрямів команд режиму робота в Agent Mail.**

### Кластери інструментів

1. **Infrastructure** → **Інфраструктура**
   - Призначення: ініціалізація контексту проєкту, перевірки здоров'я, видимість життєвого циклу сервера.
   - Приклади інструментів: `health_check`, `ensure_project`, `macro_start_session`.
2. **Identity** → **Ідентичність**
   - Призначення: створення й оновлення ідентичностей агентів і метаданих профілю.
   - Приклади інструментів: `register_agent`, `create_agent_identity`, `whois`.
3. **Messaging** → **Повідомлення**
   - Призначення: асинхронне узгодження через довговічні гілкові повідомлення.
   - Приклади інструментів: `send_message`, `reply_message`, `fetch_inbox`, `acknowledge_message`.
4. **Contacts** → **Контакти**
   - Призначення: керування тим, хто кому може писати між командами і проєктами.
   - Приклади інструментів: `request_contact`, `respond_contact`, `set_contact_policy`.
5. **File Reservations** → **Резервування файлів**
   - Призначення: оголошення наміру володіння файлами та зниження конфліктів під час паралельних редагувань.
   - Приклади інструментів: `file_reservation_paths`, `renew_file_reservations`, `release_file_reservations`.
6. **Search** → **Пошук**
   - Призначення: швидке відновлення контексту з історії повідомлень і архівів гілок.
   - Приклади інструментів: `search_messages`, `summarize_thread`, `search_messages_product`.
7. **Macros** → **Макроси**
   - Призначення: стискання типових багатокрокових робочих циклів у передбачувані виклики.
   - Приклади інструментів: `macro_start_session`, `macro_prepare_thread`, `macro_file_reservation_cycle`, `macro_contact_handshake`.
8. **Product Bus** → **Шина продукту**
   - Призначення: пов'язування кількох репозиторіїв під єдиною координаційною поверхнею рівня продукту.
   - Приклади інструментів: `ensure_product`, `products_link`, `fetch_inbox_product`.
9. **Build Slots** → **Слоти збірки**
   - Призначення: обмеження дорогих збірок і тестів для уникнення суперництва за спільні ресурси.
   - Приклади інструментів: `acquire_build_slot`, `renew_build_slot`, `release_build_slot`.

### Ресурси

- `resource://inbox/{agent}` — швидке читання останніх повідомлень вхідної скриньки.
- `resource://thread/{thread_id}` — знімок історії гілки одним читанням.
- `resource://agents/{project_key}` — перелік відомих агентів і контактних ідентичностей.
- `resource://file_reservations/{project_key}` — перегляд активних резервувань і часу спливання.
- `resource://contacts/{agent}` — граф контактів і стан схвалення.
- `resource://metrics/{project_key}` — знімок телеметрії пропускної здатності, затримки і збоїв.
- `resource://health` — готовність сервісу та сигнали деградації.

### Напрями команд режиму робота

1. **Situational Awareness** → **Оперативне орієнтування**
   - Мета: швидко отримати стан перед будь-якою дією.
   - Приклади: `am robot status --format toon`, `am robot health --format json`.
2. **Message Triage** → **Розбір повідомлень**
   - Мета: пріоритезувати вхідні задачі координації та підтвердити їх.
   - Приклади: `am robot inbox --format json --agent GreenCastle`, `am robot thread --format md br-123`.
3. **History Retrieval** → **Відновлення історії**
   - Мета: витягнути попередні рішення перед новими змінами.
   - Приклади: `am robot search --format json "auth refactor"`, `am robot thread --format md br-123`.
4. **Edit Safety** → **Безпека редагування**
   - Мета: перевірити володіння і не врізатися в чуже резервування.
   - Приклади: `am robot reservations --format json`, `am robot health --format json`.
5. **Operator Reporting** → **Операторська звітність**
   - Мета: згенерувати машинозчитувані знімки для автоматизації та панелей.
   - Приклади: `am robot status --format json > status.snapshot.json`, `am robot health --format json > health.snapshot.json`.

## Текстові елементи заголовка документа

- Значок категорії відображає категорію документа.
- Плашка файла показує `filename`.
- Основний заголовок документа показує `doc.title`.
- Підзаголовок показує `doc.description`.

## Поведінка завантаження і помилок

- Під час завантаження рендериться skeleton-оболонка читача.
- Якщо документ не відкрито, на настільному режимі показується окремий порожній стан.
- При помилці завантаження відображається текст на кшталт `Failed to load <filename>`.
